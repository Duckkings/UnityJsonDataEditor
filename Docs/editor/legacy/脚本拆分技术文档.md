# UnityJsonDataEditor 脚本拆分技术文档

- 日期：2026-03-31
- 状态：拆分实现已完成
- 适用范围：当前仓库中的 `script.js`
- 当前基线：`script.js` 为单文件 IIFE 结构，约 `8921` 行，顶层命名函数约 `250+`
- 目标：按职责拆分脚本，降低单文件耦合度，确保目录加载、三列编辑、表格模式、CSV、垃圾箱、保存、Unity C# 生成、UE C++ 生成可以独立维护

## 当前主流程

### 1. 启动流程

当前启动链路如下：

`DOMContentLoaded`
-> `autoRestoreLastDirectory`
-> `getLastDirectoryHandle`
-> `verifyPermission`
-> `loadEditorConfigState`
-> `ensureSubFolders`
-> Unity 模式下执行 `ensureModelStruct`、`generateRuntimeLoaderArtifacts`
-> `loadAllTemplates`
-> `refreshTemplates`
-> `updateIndexTemplateOptions`

补充说明：

- 当前文件内存在两处 `DOMContentLoaded` 绑定，拆分后应合并到统一入口。
- 启动流程同时承担目录恢复、配置恢复、运行时脚本准备、模板装载、UI 刷新，职责过重。

### 2. 编辑流程

当前编辑链路如下：

用户操作 `newTemplate` / `newInstance` / `newParam` / `renameTemplate` / `renameInstance` / `updateParamValue`
-> 修改全局 `templates`、选择集、当前索引
-> `refreshTemplates`
-> `refreshInstances`
-> `refreshParams`
-> `updateIndexTemplateOptions`
-> 表格模式下补充 `commitActiveSheetEdits` / `renderLuckysheetForActiveInstance`

补充说明：

- 现在的数据变更、UI 重绘、校验提示、日志提示混在同一层。
- `refreshTemplates`、`refreshInstances`、`refreshParams` 是当前三列模式的核心渲染入口。

### 3. 保存流程

当前保存链路如下：

`saveAll`
-> `commitActiveSheetEdits`
-> `ensureEngineGenerationConsent`
-> `cleanConflictingEngineArtifacts`
-> `ensureSubFolders`
-> Unity 模式下执行 `ensureModelStruct`
-> `ensureTrashDirectory`
-> 遍历模板并做结构差异判断
-> 写入 JSON
-> 处理待删除模板并转移垃圾箱
-> Unity 模式执行 `generateEnumCSFiles`、`generateRuntimeLoaderArtifacts`
-> UE 模式执行 `generateUECppStructuresForCurrentTemplates`
-> `writeManifestForTemplates`
-> `persistEditorConfig`
-> 刷新垃圾箱、日志、提示消息

补充说明：

- `saveAll` 现在同时承担表格提交、结构比较、文件写入、垃圾箱迁移、代码生成、日志汇总、UI 提示，是最需要优先拆分的函数之一。

### 4. CSV 导入导出流程

当前导出链路如下：

`beginExportSelection`
-> `handleTemplateExportCheckbox` / `handleInstanceExportCheckbox`
-> `collectTemplatesForExport`
-> `buildCsvRowsForTemplate`
-> `performExportCsv`

当前导入链路如下：

`importFromCsv`
-> `parseCsvText`
-> `buildTemplateFromCsv`
-> `applyImportedTemplate`
-> `refreshTemplates` / `refreshInstances` / `refreshParams`

### 5. 代码生成流程

Unity 生成链路如下：

`generateCSContent`
-> `generateEnumCSFiles`
-> `generateRuntimeLoaderArtifacts`

UE 生成链路如下：

`generateUECppStructuresForCurrentTemplates`
-> `generateUEEnumHeaderFiles`
-> `buildUEHeaderContent`
-> `cleanupCppEnumDirectory`

## 1. 功能拆分（完成）

### 拆分原则

- 领域函数优先纯函数化，不直接访问 DOM，不直接写文件。
- UI 模块只负责渲染、事件响应和界面状态同步，不直接决定持久化细节。
- 文件系统、IndexedDB、配置、代码生成统一放到服务层。
- 保存、导入、恢复、生成这类跨模块流程由入口控制器统一编排。
- 保持 `templates`、当前选中索引、模式状态为共享状态对象，不再散落为全局局部变量。

优先级建议如下：

1. `M05 索引、枚举与数据校验`
2. `M03 模板归一化与结构快照`
3. `M04 存储、配置与工作区`
4. `M10 运行时与 C# 生成`
5. `M11 UE 生成`
6. `M06 表格模式`
7. `M09 模板持久化`
8. `M13 三列面板渲染与对比`

- 最后处理 UI 面板和事件绑定，避免在一开始就大规模改 DOM 逻辑。

## 2. 拆分实现（完成）

### 实现方案

推荐采用浏览器原生 ES Modules，不引入构建工具，入口改为：

```html
<script type="module" src="./src/main.js"></script>
```

前提说明：

- 该工具本身就依赖安全上下文和本地服务方式运行，使用 ESM 是可接受的。
- 如果后续必须继续兼容“直接双击打开 `index.html`”，则第一阶段可先拆成多个传统脚本文件并挂到 `window.AppModules`，第二阶段再切换到 ESM。

### 共享对象设计

拆分后统一保留 3 个共享对象：

- `appState`：保存模板数据、当前选中索引、编辑模式、引擎模式、导出状态、日志、垃圾箱状态。
- `domRefs`：缓存 DOM 元素引用，避免各模块重复 `getElementById`。
- `appServices`：聚合 `workspaceStorage`、`templatePersistence`、`csvService`、`csharpGenerator`、`ueGenerator` 等服务。

### 阶段 1：建立入口和共享状态

目标：

- 建立 `src/main.js`
- 建立 `appState`
- 把现在文件头部的全局状态变量收口

执行动作：

- 将模式、当前选中索引、目录句柄、导出状态、日志状态、垃圾箱状态迁入 `appState`
- 将 DOM 引用提取为单独的 `createDomRefs()` 或静态对象
- 合并两处 `DOMContentLoaded`

验收标准：

- 页面能正常打开
- 自动恢复目录仍能工作
- 目录选择后能正常加载模板

### 阶段 2：先抽纯函数模块

目标：

- 先把不直接依赖 DOM 和文件句柄的函数拆出去

执行动作：

- 抽出 `M03 template-normalizer`
- 抽出 `M05 index-enum-validation`
- 抽出 `M02 form-and-reference` 中的纯函数部分
- 抽出 `M12 editor-actions` 中的值转换和默认值逻辑

验收标准：

- 新建模板、实例、参数仍可正常工作
- 索引重复、无效引用、列表值错误提示仍一致
- Enum 行为与当前版本一致

### 阶段 3：抽工作区与持久化服务

目标：

- 让文件系统访问和 IndexedDB 访问退出 UI 层

执行动作：

- 抽出 `M04 workspace-storage`
- 抽出 `M09 template-persistence`
- 将 `loadAllTemplates` 改为“返回模板数据 + 元信息”，由入口决定何时刷新 UI
- 将 `saveAll` 拆为小步骤函数

建议内部小步骤：

- `prepareSaveContext`
- `collectTemplateWritePlan`
- `writeTemplateJsonFiles`
- `processTemplateDeletions`
- `runPostSaveGenerators`
- `finalizeSaveAndNotify`

验收标准：

- 选择目录、自动恢复、保存、删除模板进垃圾箱、恢复模板全部可用
- `manifest.json` 输出不变

### 阶段 4：抽代码生成器

目标：

- 将 Unity 和 UE 生成逻辑从保存流程中解耦

执行动作：

- 抽出 `M10 csharp-runtime-generator`
- 抽出 `M11 ue-generator`
- 让生成器输出“待写入文件列表”或直接输出字符串映射
- 持久化服务统一负责写入磁盘

验收标准：

- Unity 模式下 `.cs` 结果与拆分前一致
- UE 模式下 `.h` 结果与拆分前一致
- 引擎切换仍会清理互斥目录

### 阶段 5：抽表格模式与三列 UI

目标：

- 分离 Luckysheet 逻辑与三列模式逻辑

执行动作：

- 抽出 `M06 sheet-mode`
- 抽出 `M13 panels`
- 将 `refreshTemplates`、`refreshInstances`、`refreshParams` 仅保留为 UI 渲染入口
- 将数据修改放回 `M12 editor-actions`

验收标准：

- 三列模式编辑正常
- 表格模式切换、提交、导航、重复高亮正常
- 经典模式与表格模式切换后数据一致

### 阶段 6：抽交互和系统面板

目标：

- 把快捷键、搜索、复制粘贴、参数历史、日志、垃圾箱从主文件剥离

执行动作：

- 抽出 `M14 interaction`
- 抽出 `M08 system-panels`
- 将快捷键绑定全部放回 `src/main.js`
- 将垃圾箱恢复后的刷新行为交给统一控制器

验收标准：

- `Ctrl+C` / `Ctrl+V` / `Delete` / `F1` 正常
- 搜索过滤正常
- 垃圾箱打开、恢复、删除、清空正常

### 阶段 7：清理旧入口

目标：

- 将旧 `script.js` 降级为历史版本或直接删除

执行动作：

- 所有模块改为显式 `import` / `export`
- 清理重复状态变量
